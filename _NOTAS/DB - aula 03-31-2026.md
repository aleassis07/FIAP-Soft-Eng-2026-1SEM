id primário sempre pertence a uma tabela dimensional que contém as informações primárias de registro

aula passada construímos o modelo lógico
hoje vamos construir o modelo relacional

modelo relacional = podemos chamar de tabela

usamos o Oracle SQL Developer Data Modeler

celular e email podem atuar como PK porque são UNICOS e servem para identificar uma pessoa

chave prata = chave primária

aqui estamos construindo a arquitetura da tabela ao fazer o modelo relacional
equivale à planta da casa... a planta do banco de dados

cardinalidade mostra quem é a chave primaria, quem é a chave estrangeira e quantas vezes a PK ou FK pode aparecer em uma das duas tabelas
PK nao pode aparecer 2 vezes na mesma tabela = 1 para muitos

na cardinalidade, não é uma seta, mas sim o triangulo... nao indica a direção!!

se você faz um modelo lógico detalhado, você consegue criar a versão relacional do seu banco, por meio da opção de seta no oracle sql developer data modeler
